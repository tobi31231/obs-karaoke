# OBS Karaoke Aligner MVP

로컬에서만 실행되는 OBS용 노래방 자막 프로토타입입니다.

## 설치

1. GitHub Releases에서 `OBS-Karaoke-Setup.exe`를 받습니다.
2. 설치기를 실행합니다.
3. 설치 완료 후 바탕 화면의 `OBS Karaoke MVP`를 실행합니다.
4. 서버 준비가 끝나면 EXE 창 안에 조작 화면이 표시됩니다.
5. EXE 창을 닫으면 로컬 서버, 분석 작업과 내장 화면 프로세스도 함께 종료됩니다. OBS 자체는 종료하지 않습니다.

별도 브라우저나 OBS 브라우저 창을 자동으로 실행하지 않습니다. 앱 화면을 표시하는 WebView2 프로세스는 앱 실행 중에만 필요합니다. 화면의 임시 프로필은 종료할 때 삭제하며 모델 파일은 유지합니다.

설치기는 앱 본체, Turbo 모델, Python, Node.js, CUDA 런타임과 필요한 경우 Microsoft Edge WebView2 Runtime을 설치합니다. 최초 설치에는 인터넷 연결과 약 4.5GB의 디스크 공간이 필요하며, 설치 후 분석은 오프라인으로 작동합니다.

### 소스에서 실행

1. Node.js 18 이상을 설치합니다.
2. Python 환경에 `requirements-whisper.txt`를 설치합니다.
3. `work/download_model.py turbo`로 모델을 준비합니다.
4. 이 폴더에서 실행합니다.

```powershell
npm start
```

5. 브라우저에서 `http://127.0.0.1:5177`을 엽니다.
6. OBS Browser Source에는 `http://127.0.0.1:5177/overlay`를 넣습니다.

## 사용 흐름

1. 분리한 **보컬 트랙**과 **MR 트랙**을 각각 선택합니다. MP3, WAV, M4A, MP4 같은 파일을 넣을 수 있습니다.
2. 타임코드가 없는 TXT 가사 파일을 선택합니다. 두 트랙은 같은 버전에서 분리한 파일이며 시작점과 앞부분 무음을 유지해야 합니다. 길이 차이가 있으면 경고가 표시됩니다. 서로 다른 버전의 트랙을 자동으로 맞추는 기능은 없습니다.
3. `자동 싱크 생성`을 누릅니다.
   - 줄바꿈 없이 길게 작성된 단락은 Turbo 전사 시각, 음성 사이의 쉼, 문장부호를 기준으로 자동 분할됩니다.
   - 이미 짧게 줄을 나눈 가사는 사용자가 작성한 줄을 그대로 유지합니다.
4. 분석을 중단하려면 로딩창의 `분석 종료`를 누릅니다. 실행 중인 로컬 GPU/CPU 작업도 같이 종료됩니다.
5. 보컬과 가사가 사실상 다른 경우 `보컬/가사 불일치`가 표시됩니다. 분석에는 보컬만 사용하며 MR은 분석 엔진에 보내지 않습니다.
6. 앱 플레이어에서 두 트랙이 같은 오디오 시계로 재생되며 OBS overlay도 이를 따라갑니다. 트랙별 음량을 조정할 수 있고, 보컬 음량을 0으로 해도 가사 분석 결과는 유지됩니다.
7. 어긋난 줄은 편집표에서 `-0.5`, `-0.1`, `+0.1`, `+0.5` 버튼으로 보정합니다.
8. 구간 전체가 밀리면 해당 줄을 선택하고 `선택 줄 현재로 고정`을 누릅니다. 고정된 줄을 기준으로 앞뒤 줄이 같이 재배치됩니다.
9. 전체가 빠르거나 느리면 `전체` 보정 버튼을, 특정 지점 이후만 밀리면 `선택 줄부터` 보정 버튼을 사용합니다.
10. `가사 채우기 애니메이션`을 끄면 현재 가사가 기본 글자색으로 표시됩니다. 줄 전환과 다음 줄 표시는 유지됩니다. JSON 내보내기에는 이 설정도 포함됩니다.

가사에 없는 허밍·효과음은 독립 음성 인식 결과와 가사를 비교하는 기존 정렬 과정에서 건너뛸 수 있지만, 짧은 감탄사나 반복 허밍을 항상 정확하게 구별한다고 보장하지는 않습니다. 실제 부르는 허밍을 표시하려면 TXT에 `음`, `라라라`처럼 넣고 결과를 확인하세요. 분석 실패 시 파형만으로 임의의 타이밍을 생성하지 않습니다.

## 개발자 진단 로그

- 앱 화면에서 `F12`를 2.5초 안에 5번 누르면 개발자 모드가 켜지거나 꺼집니다.
- 개발자 모드는 정렬 후보 품질, 매칭/구제/강제 정렬 줄 수, 자동 타이밍과 사용자 보정 결과의 차이를 기록합니다.
- 로그는 메모리에만 보관되며 `진단 로그 내보내기`를 눌렀을 때만 JSON 파일로 저장됩니다.
- 로그에는 음원과 가사 원문, 파일명, 전체 경로, 사용자 정보가 포함되지 않습니다.

## MVP 범위

- 외부 API나 클라우드 서비스는 사용하지 않습니다.
- Turbo 모델은 로컬 PC에서만 실행합니다. NVIDIA GPU가 있으면 CUDA를 우선 사용하고, 실패하면 CPU로 전환합니다.
- 오디오는 로컬 Python 정렬 엔진에서만 분석합니다.
- 서버는 현재 재생 위치와 타임라인을 overlay에 전달합니다.
- Turbo 모델이 준비되어 있으면 단어 타임스탬프를 포함한 로컬 Whisper 분석을 먼저 사용합니다.
- 긴 가사는 전사 결과로 먼저 줄을 나눈 뒤 전체 곡의 단어·문자 앵커로 다시 정렬해, 한 지점의 오차가 이후 모든 줄에 누적되지 않게 합니다.
- 같은 가사가 3회 이상 연속되면 앞뒤의 고유 가사를 앵커로 삼아 반복 횟수와 박자 간격을 별도로 강제 정렬합니다.
- 모델 패키지가 없거나 분석 오류가 발생하면 오류를 표시하고 중단합니다.
- 독립 음성 인식 결과가 가사와 거의 일치하지 않거나 보컬을 감지하지 못한 경우에는 임시 싱크를 만들지 않습니다.
- 실제 제품 단계에서는 같은 인터페이스에 WhisperX, Montreal Forced Aligner, whisper.cpp 계열 로컬 forced alignment 엔진을 붙이면 됩니다.

## 개인정보/비용

- 오디오와 가사는 외부 서버로 업로드하지 않습니다.
- API 과금은 없습니다.
- 최초 설치 시 GitHub Release에서 모델과 런타임을 내려받습니다.
- 분석은 사용자의 PC 성능으로 실행됩니다.

## 배포 빌드

- `scripts/build-release-assets.ps1`은 검증된 portable 폴더를 GitHub의 파일당 2GiB 제한에 맞는 자산으로 분리합니다.
- 설치기는 옆에 Release 자산이 있으면 로컬 파일을 사용하고, 없으면 GitHub Release에서 내려받습니다.
- 음원, 가사, 분석 결과, 모델과 런타임 바이너리는 Git 저장소에 커밋하지 않습니다.

## OBS 권장 설정

- URL: `http://127.0.0.1:5177/overlay`
- Width: 1920
- Height: 1080
- Custom CSS는 비워도 됩니다.
- 배경은 투명입니다.
